# 案例：TypeScript Guide / Agent Dev Foundations 教程站复刻

## 证据范围与结论

整理于 2026-10-13，依据当前会话的用户要求、项目中的源码取证与验证记录。参考 UI 是 `Windy3f3f3f3f/how-claude-code-works`，采用 commit `f4d6505ed9162a0ee6be089190f74c419ecacb19`；教程来源为 WangDoc。

早期全部实现回复、每一版旧代码与完整逐像素比较并未保留在本次可读材料中。因此，以下把用户观察、文档明确记载的机制、已验证修复与推断分开，不虚构某次提交或模型内部动机。项目中仍写 71 篇、三分区或速查的旧记录属于对应历史阶段。

主要返工来自**参考结构与插件行为取证不充分，先自创外壳，后逐项对齐**。Astro 静态架构并不是已证实的障碍。剩余差异中有一部分是用户要求或已登记技术适配，不能统称为未修 bug。

## 为什么起初不像

### 1. 用熟悉的目录方案替代真实结构

用户初始要求章节导航与页内目录，但没有指定左右双栏。参考站是名称、搜索、目录在同一个全高侧栏内滚动；初版双侧目录、之后的 Tabs/固定头部/折叠组改变了层级与操作。

证据：原项目 `docs/UI-REFERENCE.md:27–29,61–64` 记录参考骨架及被替代方案；`docs/reference/theme-notes.md:94–117` 记录目录机制。分类：复刻偏离；不能说左右双栏是用户强制要求。

可复用措施：先记录真实 DOM、滚动归属和各级节点角色，再接入长文。参考存在时，设计偏好不能代替证据。

### 2. 主题 CSS 不包含全部插件结构和交互

分页的明确旧问题是“两个链接、字符箭头和两行文字”，缺原版 `.pagination-item` 外层、SVG、分组副标题及插件 CSS。默认/hover 的透明度和下划线自然不同。修复采用 docsify-pagination 2.10.1 的真实结构与样式。

证据：`docs/reference/pagination-notes.md:73–80` 明确描述旧缺口；`:82–92` 说明分页只生成普通链接，普通导航回顶部来自 Docsify `auto2top`，历史来源有单独处理。

复制按钮同样由主题、插件 DOM、状态类和计时共同决定。原样替换按钮文字无法复现弹出反馈。取证确认成功/失败 1 秒复位，而 1.5 秒是另一个强制 blur；本项目保留键盘焦点，未照搬 blur。

证据：`docs/reference/copy-notes.md:29–55`。分类：分页组件复刻不完整；复制文档证明机制与修复范围，不足以断言所有状态都曾实际失败。

可复用措施：为每个控件追到模板、注入样式、主题覆盖与事件归属；默认、hover、focus、成功、失败分别对照。

### 3. 目录的归属、活跃状态和滚动是三个问题

用户依次报告分区展开错位、两个定位条、点模块后目录回顶部。实际修复分别为：按所属分区嵌套节点；章与 H2 的位置边线设明确优先级；按分区及桌面/手机容器记住侧栏位置，只有目标不可见时最小调整。

证据：`docs/REFERENCE-VERIFICATION.md:7–9` 记录实际验证；`src/components/SidebarNav.astro`、`src/styles/global.css`、`src/scripts/reader.ts` 保存最终实现。旧版选择器和状态代码未完整归档，不能声称已经证明每个故障的唯一引入原因。

搜索聚焦的问题有“满宽布局与原光晕补齐”的验证证据，具体旧 selector 冲突未被独立保留，也不应虚构。

可复用措施：正文位置、侧栏位置、焦点、当前章和当前小节分别建状态契约，再测侧栏/搜索/翻页/直开/刷新/历史/手机开关。不是每个问题都靠给 active 再加一条 CSS 解决。

### 4. 构建与有限截图覆盖不了阅读路径

多轮类型检查和正文检查通过，仍出现视觉/交互反馈。它们验证源码、内容与链接，不证明 hover、滚动恢复或窄屏对话框行为相同。

证据：`docs/READING-INTERACTIONS.md:7–15` 的后续操作矩阵与 `docs/NAVIGATION.md` 的历史边界。不能用旧截图替代新组件验收，也不能把原 CSS 字节一致扩大成全站像素一致。

可复用措施：自动数据检查与浏览器状态检查各自交付证据；最终按已测范围下结论。

## 哪些不是复刻 bug

- 最初明确要求每篇速查、来源与相关条目，后来用户明确取消展示；这是需求变化。阅读提示的内容准确性目的与冗余呈现也应分开看。把本次“去掉”写成所有教程站禁用这些内容，会再次偏离用户目标。
- 用户要求提高可读性，最终正文 18px、代码 16px、侧栏 300px；参考正文 15px、侧栏 260px。`55em` 随基础字号改变行宽，这是有意差异，无法同时声称像素完全相同。
- 静态独立 URL 和构建时高亮是有记录的技术适配。手机原生 dialog 曾被登记为适配，但后来用户明确拒绝；它已被推移布局替代，旧登记不能继续为当前偏差辩护。
- HTML/ES6 全收录与项目配置并入 TS 都是后续范围调整，不是初版漏做已确认范围。
- 在线 TLS 错误是外部取证阻塞；本地参照解决了取证入口，不足以解释或正当化所有自创 UI。

证据位置：原项目 `docs/SCOPE.md`、`docs/READABILITY.md:17–27`、`docs/UI-REFERENCE.md` 的有意差异表。原要求与当前呈现相冲突时，以最后明确要求为准，保留必要来源记录。

## 内容扩充暴露的可复用边界

- 只按上游目录会漏 HTML 的 mobile，以及 ES6 的 acknowledgment、fp、mixin、simd、temporal。真实 docs 全集才是清点依据。
- 六个同名在线路径返回 HTTP 200 的首页，不能作为文章可达证据；固定源码链接提供准确来源。
- HTML 的真实示例表格与 ES6 的上标需正常呈现，HTML 标签标题和 fenced script 必须保持文本。全关 HTML 与全开 HTML 都不满足这个混合内容契约。
- 固定 Git blob 字节避免 Windows 换行转换损坏来源哈希。版本/哈希从准备材料迁入统一来源锁，避免两处账本分叉。
- UI MIT、各教程的 CC 声明与 MDN 配图署名分别取证；本次仓库/在线声明差异不是可以推广到下一仓库的固定许可结论。

证据位置：原项目 `docs/HTML-SOURCE.md`、`docs/ES6-SOURCE.md`、`docs/HTML-ES6-VERIFICATION.md`、`sources.lock.json` 及对应许可记录。该案例当前已验证内容与阅读功能，未宣称全部教程示例执行、跨浏览器全覆盖或严格像素等价。

## 后续修复与发布

### 2026-10-15 补记：后续修复与发布

项目后改名为 Agent Dev Foundations。用户要求恢复主题按钮与 GitHub 角标，实际复用 SVG 和原 CSS；本例角标 70px、按钮 34px、工具组 top 12px/right 100px 是案例证据，不是其他项目默认值。

手机截图揭示模态抽屉与参考推移行为不同。修复删除独立 X、灰色遮罩和第二份目录，恢复外层 main 内的按钮、aside 与相邻 section.content。按钮外壳原为 div，旧实现用 span 会被主题通用 span/nth-child 规则误选。外层 main 的 overflow-x:hidden 负责裁切推移正文，单删 dialog 仍可能撑出横向滚动条。

手机恢复参考的 260px，桌面保留用户要求的 300px；原主题展开会将汉堡旋成 X，但用户明确不要 X，故保留汉堡并登记差异。收起时仅垂直定位标题，避免 transform 过渡中的 scrollIntoView 造成横向偏移。390×844 模拟对照的侧栏宽度与坐标一致，验证了正文点击收起、搜索、锚点、Escape 及桌面回归；未做 iPhone 真机测试。

用户先要求仅本地 review，再明确要求发布。仓库子路径需适配搜索、资源和重定向；部署后比对公网与对应 CI 产物，而不是凭 push 成功宣布上线。公网浏览器工具曾超时，HTTP/哈希只作为补充，未宣称线上交互全部通过。

证据为项目 `docs/reference/mobile-sidebar.md`、`top-controls.md`、`docs/VERIFICATION.md`，手机修复发布提交为 `494f79ea6daffcfa22bbc3e30a380a28e97938a7`。这些案例事实不自动授予后续任务发布或目录迁移权限。
