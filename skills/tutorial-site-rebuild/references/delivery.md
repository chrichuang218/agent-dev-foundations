# 交付、路径与发布

仅在教程站任务涉及改名、预览服务或发布时读取。平台、端口、版本按目标项目确认，不把案例中的 GitHub Pages 或数值设为通用要求。

## 授权与版本

用户要求先本地 review 时，完成实现、构建与浏览器验证并提供预览，保持远端和线上不变。之后明确要求部署发布，才继续相应的提交、推送、发布与部署范围；已有充分授权不重复询问。

开始前核对 Git 状态、远端和标签，保护未提交文件，避免混入其他改动。用受控提交触发 CI，等待该提交的检查与部署完成，再将 Release/tag 固定到同一提交；push 成功不等于部署成功。

## 托管子路径

分别验证本地根路径与目标发布路径：文章、目录、翻页、搜索请求及索引 URL、图片、样式、脚本、图标、许可引用和旧入口跳转。使用框架原生 base 与显式路径适配，保持逻辑文章 ID 独立；检查脚本识别同一前缀。

canonical 是元数据而非运行时资源；检查应区分它与脚本、样式、图片加载，不能为了避错放松内部目标与资源检查。

下载包优先使用通过 CI 且实际部署的产物，记录提交、运行地址和 SHA-256。上线后核查页面身份、关键资源及实际变更，必要时比对公网与 CI 文件字节。浏览器不可用时明确未验证范围，不用 200 或哈希一致声称交互全部通过。

## 服务与目录改名

核对实际目录、Git 身份、目标冲突及服务的命令、进程、工作目录和端口。部分工具同一项目只允许一个预览实例，应使用其停止/重启机制，不在未就绪时反复开页面，也不批量结束无关进程。

改名分别处理产品标题、包名和 lockfile、图标、当前文档、本地目录。历史来源与截图、兼容存储键可保留原名并说明用途，不无差别替换教程原文。

Windows 目录被占用时先查明相关服务与工具会话。若选择迁移内容，先核验绝对源/目标路径和冲突，完整保留隐藏 `.git`、用户文件和未提交状态；中断后先盘点两端再继续，不覆盖已有目标或提前声称完成。审批拒绝时保留现场、报告具体限制，不换工具绕过删除。清理失败与有效仓库是否迁移成功分别核实。

完成后从实际目录核对 Git 根、配置和构建，恢复所需预览，说明遗留目录及后续操作位置。上述处理仅作用于用户已授权的目标，不是关闭其他应用或清理其他项目的许可。
