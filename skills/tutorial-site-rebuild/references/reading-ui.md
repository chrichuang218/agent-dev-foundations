# 阅读界面取证与状态矩阵

用于教程站的代表页和交互验证。只执行目标实际保留的功能；在项目契约中说明不适用项，不为清单增加功能。

## 参考外壳怎么取证

先在同一视口、相同缩放和主题下打开真实长文，观察：

- 页面骨架：侧栏、正文、页内目录、搜索与工具按钮的 DOM 父子关系。
- 滚动归属：window、正文面板、侧栏面板；哪些标题或搜索框随哪个容器滚动。
- 导航语义：分区入口、分组标题、文章链接、H2/H3 小节分别是否可点击、可折叠。
- 几何：侧栏宽度、正文最大宽度、padding、字号、行高、标题间距、窄屏断点。记录计算值与视口，不只记录 CSS 字面值。
- 依赖：主题 CSS → 原站覆写 → 插件注入样式 → 当前项目兼容层；检查选择器优先级及媒体查询。插件名称要追到实际模板、SVG 和状态类。

先保留可复核的源文件/摘录、版本和定位，再实现目标。读取插件字符串中的 CSS 不必执行插件代码。源站真实运行结果和已审源码共同解释行为，截图负责证明可见结果。

正文使用 `em/rem` 布局时，提高基础字号也可能扩大正文宽度、间距和控件尺寸。逐项实测关联尺寸，依据用户可读性目标决定保留或独立约束，而不是照搬案例的 18px/300px。

## 状态矩阵

### 手机侧栏与工具控件

1. 在相同窄屏宽度检查收起和展开状态。记录侧栏与正文的 x 坐标、宽度、外层 overflow、按钮点击区、遮罩、滚动锁定和焦点行为，区分推移式、覆盖式与模态式。
2. 追踪 DOM：外层裁切容器、相邻选择器（如 `.sidebar + .content`）、`div`/`span` 标签与 `nth-child`。缺少外层可能让推开的正文撑出横向滚动条；改错标签可能使图标外壳也被旋转。原始 CSS 必须搭配正确结构。
3. 推移式参考优先复用一个目录。模态 `dialog` 的遮罩、自动聚焦、焦点限制和额外关闭按钮是独立行为，只有用户明确要求时才替换。非模态结构仍需处理隐藏目录的键盘可达性、Escape 和焦点恢复，避免重新造一套模态体验。
4. 分别操作菜单按钮、露出的正文、文章链接、锚点、搜索输入/结果、目录折叠及断点切换。哪些动作收起、哪些保持展开，以参考和用户修正为准；原站无滑动手势时不自行补 swipe。
5. 用户明确取消 X、遮罩或其他控件时，删除对应结构和状态代码，登记与参考的差异。不把本次偏好推广成所有项目的通用禁令；宽度也从本项目证据确定。

主题按钮和 GitHub 角标要核对真实 DOM/SVG、尺寸、定位、字形、hover/active 动画与偏好持久化。保留原样式和结构，再适配本站链接、品牌与可访问名称；去掉参考品牌不等于顺手去掉交互控件。

### 阅读操作

| 对象 | 需实际触发的状态 | 判据与常见失败 |
| --- | --- | --- |
| 分区与分组 | 切分区、打开靠后章节、折叠顶层 | 当前章嵌在所属分区下；分区折叠与文章小节折叠相互独立；其他分区不被塞入当前章末尾 |
| 当前章与页内目录 | 页顶、进入 H2、页底、折叠小节 | 用来源规定的高亮优先级；若设计只有一个位置标记，章与小节不能同时画两个；长标题截断方式与提示可用 |
| 搜索 | idle、focus、查询、无结果、清空、失败 | 对照宽度、焦点样式、摘要、结果排序/数量；清空后的焦点与目录是否保留由源站/用户契约决定 |
| 搜索跳转 | 文章结果、小节结果、同页 hash、跨页 hash | 索引 URL 与实际渲染 ID 相同；跳到对应小节，不总回标题；取消旧请求/结果避免覆盖新查询 |
| 翻页 | 第一篇、中间篇、末篇、跨组/区、hover、focus | 名称、序号、SVG、层级、副标题与原组件对应；缺邻居时不生成假链接；分页顺序与目录一致 |
| 代码复制 | 鼠标、键盘、真实成功、受控失败 | 复制原代码且不带按钮文案；成功/失败样式和复位时序一致；不吞失败，也不为模仿旧实现强行移走键盘焦点 |
| 主题与工具 | 切换、刷新、返回顶部、隐藏/恢复侧栏 | 明暗正文、代码、表格对比度正常；实际滚动容器正确；保留用户选项，不恢复被取消的控件 |
| 窄屏 | 长标题、代码、表格、图片、开关目录、Escape | 代码/表格仅在各自容器横向滚动，整页不被撑宽；图片保比例；菜单焦点约束/恢复按实现类型验证 |

## 各种入口不能共用一个粗暴滚动规则

| 入口 | 正文 | 侧栏 |
| --- | --- | --- |
| 普通章节链接/上一篇/下一篇 | 按参考站契约进入页顶；含 hash 时定位标题 | 保持或恢复目录位置，当前章不可见才最小调整 |
| 搜索小节或页内锚点 | 定位目标，不被自动回顶覆盖 | 展开目标章，位置标记对应正文 |
| 直接 URL、刷新 | 有 hash 时仍定位；其余尊重已确认的刷新契约 | 当前章可见、父分区正确 |
| 浏览器后退/前进 | 按浏览器/路由历史恢复，不被通用 `scrollTo(0,0)` 抹掉 | 恢复适用的状态，不强制滚正文 |
| 手机关开目录 | 正文保持；点小节后关闭并聚焦目标（若为目标契约） | 打开且有布局后再恢复位置 |

先定位位置丢失发生在哪一层：组件链接、客户端路由、完整页面加载、浏览器历史、焦点或容器。静态站可按分区及桌面/手机容器保存侧栏 scrollTop；这是可选实现，不是必须使用 sessionStorage 的要求。

自动跟随当前小节时，只移动超出可视区的侧栏项。用户正在鼠标/键盘操作目录或搜索时避免抢滚动。对侧栏节点调用 `scrollIntoView()` 前核对是否会连正文/外层一起滚。

## 真实比较与排障

推移侧栏收起时，正文的 transform 可能尚未归零。此时 `scrollIntoView()` 可能同时改变外层 scrollLeft，动画结束后正文仍横向错位。需要即时定位时仅调整垂直滚动并保留标题偏移，或等待有界的动画完成条件；验收同时看标题位置、window.scrollX 和外层 scrollLeft，不能只看 hash 已变化。

1. 状态相同再比较：视口、缩放、主题、hover/focus、滚动位置、字体加载、浏览器环境。
2. 外观不符先检查 DOM 结构、插件样式与覆盖顺序；例如两条简单链接不等于带容器、SVG 和副标题的分页组件。
3. 单页正常但跳转不符，检查导航来源和多份状态真值，不先添加更多 CSS。
4. 新版构建后刷新生产预览，防止旧 bundle/HTML 冒充新结果。存疑时检查实际页面标题、资源路径与返回内容。
5. 后台浏览器可能暂停 rAF；不要靠无限等待动画帧判定失败。使用有界的 locator/URL/布局条件，读取新状态后再行动。
6. 懒加载图片未进入视口时 naturalWidth=0 不足以证明损坏；滚到附近再检验响应、解码尺寸和完整性。记录尺寸以减少布局跳动。

截图与测量写入同一轮验证记录，指出代表页、视口、主题、构建及测试范围。共享 UI 可做同状态对照；不同正文的整页像素差不能直接解释成 CSS bug。严格同内容复刻才按 `website-rebuild` 的相应等价门验收。

- 自动化点击部分出屏的透明菜单按钮失败时，先检查可见边界和命中元素，再点击已观察到的可见区域；不要为工具方便改变布局。
- 过渡过程中的尺寸不是最终结果，读取稳定状态后再比较。浏览器超时先查服务、端口和工具状态，必要时换同一浏览器的新标签页，避免重复失败页操作。HTTP 与哈希不能冒充浏览器交互验收。
- 临时响应式测试结束恢复视口；用户明确要求“切换手机显示供 review”时保持该尺寸并显示本地页面。窄屏模拟与手机真机验证分别报告。
