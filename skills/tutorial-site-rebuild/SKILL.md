# Tutorial Site Rebuild

交付可完整查阅、可重复维护的教程站。把**参考 UI**和**内容来源**分开取证，再合并为目标网站；样板页只是确定实现方式，不能代替全部纳入内容。

## 与 website-rebuild 的分工

首次使用时读取可用技能目录中的 `$website-rebuild`，关注其适用范围、真实源码取证、差异登记与验证原则。用户指定了它但文件不可用时，说明缺失及影响；继续已授权且不依赖它的内容清点，不假装已应用。

- **同内容、同视觉与同交互的严格 1:1**：由 `website-rebuild` 主导其适用流程。本技能只补充文档内容和阅读状态检查。
- **参考 UI + 新教程内容**：本技能主导目标工程；借用 `website-rebuild` 的取证纪律，属于其 `beyond-the-rebuild` 所说明的衍生用途。先对齐参考外壳再做内容适配，无须虚构已完成整个 L1–L3 流水线。
- 参考证据与目标工程分开保存。公开仓库源码、真实主题、插件与运行页面是依据；框架名称本身不决定可否复刻。确认现有技术栈后再选方案。
- 平台允许的浏览器工具和构建工具优先；检查原技能脚本是否支持当前系统。Windows 的替代验证须写明实际范围，不能记成未运行的 POSIX 工具结果。
- 用户当前要求与已有授权优先。读技能不是提交、推送、部署、发布或修改其他技能的授权；授权的本地实现与验证持续推进，不增设阶段审批。

已有站点的局部修复只走受影响部分：目录/滚动问题读界面参考，漏章/链接问题读内容参考。复用已核实的版本与证据，不因启用本技能重新抓取全站或重做无关功能；结构或内容来源发生变化时再扩大相应检查。

## 1. 固定当前目标

读取仓库规则、真实 Git 状态和已有设计资料，保留用户文件。把以下内容记录到已有设计文档；缺少时采用 [项目契约模板](assets/rebuild-contract.md)，只保留适用项：

1. UI 参考、内容来源、目标目录，以及本次授权的动作。
2. 全部章节或明确范围；哪些页面/控件照原站，哪些已明确改变。
3. 当前保留与删除的功能。后来取消速查、增加搜索、调整分区属于需求变化，不自动等于前一版出错。
4. 已有文章 URL 和本地编辑的保留规则。

完成条件：没有把“参考风格”擅自收窄成首页配色，也没有把“完整收录”收窄成几篇样板。缺失的关键决定才询问；已明确的名称、来源和范围不反复确认。

## 2. 先理解参考站，再做代表页

阅读 [阅读界面取证与状态矩阵](references/reading-ui.md)。先查看一篇真实长文章，而非仅看首页：观察页面与侧栏各自如何滚动，追到 DOM、样式加载次序及插件行为。

- 在线访问确实失败后，转向公开源码或已有镜像；先审阅启动入口及脚本，再运行本地参照。不绕过证书警告，不反复请求同一失败地址。
- 锁定参考 commit、主题与插件的实际版本。能合法复用的 CSS、图标及组件结构优先复用；用小型、显式适配层处理目标工程差异。
- 建立“控件 → DOM/CSS/行为来源 → 适配 → 验证”的对应关系。原站没有的双栏目录、Tabs、固定头部、卡片和动画，只有用户要求或明确适配需要时才增加。
- 用两三篇覆盖长文/多级标题、密集代码、表格/长标题；源码含图片或特殊 Markdown 时纳入其中。以真实段落长度验证，不用短占位文掩盖布局问题。

完成条件：参考与目标在相同视口、100% 缩放、主题及交互状态下完成一次对照，目录结构及滚动容器已确定，必要偏差已有理由。其余全量内容继续制作，样板通过不是最终交付。

手机侧栏须先确认推移、覆盖或模态模型，并按阅读界面参考核对外层裁切容器、相邻节点、标签类型和关闭区域。原始 CSS 必须搭配真实结构；仅删除一个 X 不算行为对齐。

## 3. 接入完整内容

阅读 [内容管线与保真检查](references/content-pipeline.md)，建立源文件全集与逐章清单，独立记录 UI、正文和媒体的许可与署名。

采用适合当前项目的静态生成方案，正文保存在本地。分离锁定快照、人工编辑、生成目录与公开资源；导入可离线重跑，只覆盖明确生成物。需要补充的内容放在编辑层。

目录、当前章、前后篇和搜索从同一文章集合生成。文章 ID/URL 与分区归属分离，目录调整不必改旧 URL；保留的旧入口提供可验证跳转。对已经取消的速查/关联卡片，不再为新章节强制编造隐藏字段。

完成条件：所有纳入章都有完整正文和稳定路径，所有源文件有纳入或排除决定，本地资源与转换规则可追溯；既有编辑未被导入覆盖。

## 4. 按阅读路径验收

使用 [状态矩阵](references/reading-ui.md) 检查源站实际有、且目标范围保留的功能。先验证共享组件，再检查内容边界；不为了打勾新增源站没有的搜索或主题按钮。

- 自动检查：章节覆盖、原文段落/代码保留、唯一标题锚点、内部链接、图片、目录父级、搜索目标，以及旧 URL/重定向。HTTP 200 还需核对页面身份，避免首页回退伪装成文章。
- 构建/类型检查通过后，实际打开最终构建。桌面与窄屏核查长文、代码、表格；操作目录、搜索、翻页、复制、hash、刷新和浏览器历史等适用入口。
- 正文滚动、侧栏滚动和焦点分开观察；默认、hover、focus、展开/折叠、成功/失败状态分别验证。构建成功不能证明这些行为正确。
- 修复按证据归属到内容、组件、路由、滚动容器或 CSS；避免靠不断叠加样式掩盖结构问题。改动后重测受影响路径，保留最终截图与检查输出。

完成条件：全量内容检查通过，关键阅读路径可用，本次引入的问题处理完成。无法验证的项目标记具体原因和影响，不将历史截图当作当前验收。

## 5. 收口

涉及项目改名、本地预览服务或已授权发布部署时，读取 [交付、路径与发布](references/delivery.md)。用户要求“先本地 review”时只交付本地结果；收到新的发布指令后再核对相应版本并执行，旧授权不覆盖明确缩小后的范围。

README 提供真实安装/启动/构建命令、目录及维护方式；交付来源版本、许可证据、逐章清单、偏差和验证记录。最终说明新增/排除篇数、预览地址、验证结果与尚未验证事项。

分别报告**内容完整性、网站运行、视觉/交互、教程示例语义**。新正文会改变换行和页面高度；有限截图或原 CSS 哈希一致不证明全站像素等价。未执行相应完整流程，就不宣称 L1/L2/L3、GAP=0、100% 复刻或全部示例已运行。

需要解释“为什么总不像”或回顾本技能来源时，读取 [本次复刻案例](references/case-study.md)。其中的字号、工具版本、分区数量和去噪偏好是案例事实，不是下一项目的硬性要求。
